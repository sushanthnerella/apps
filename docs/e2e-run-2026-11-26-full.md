## Bugs found in this run

1. **Session-restore failure shows the login screen (medium).**
   - Steps: cold-start either app while the backend is unreachable (network off, or broken DNS), then tap "Try Again" or open the app again once online.
   - Actual: devotee — "Something went wrong / Could not reach Puja Vaahini. Check your internet and reopen the app." over the login screen (X-devotee-offline-coldstart.png); priest — "Connection Disconnected", no auto-retry, and "Try Again" lands on the priest login screen. In the priest case a force-stop + relaunch restored the session, so the token was not lost. At the start of the run (broken DNS) the devotee app stayed on the login screen across three relaunches and needed a real login.
   - Expected: retry automatically when the network returns and keep the user signed in.
2. **Priest app was signed out mid-booking (high, cause not confirmed).**
   - At 17:52, while a ghat booking was POOJA_STARTED and the network was up (ping and `/health` OK), the priest app showed "Connection Disconnected" and then the login screen (F7-priest-complete.png, X-priest-state.png). No crash line, nothing useful in logcat. After logging in again the booking card came back.
   - Related observation: after that in-app login, the priest API token I had obtained at the start returned `401 {"error":"unauthorized"}`, so a new login appears to revoke earlier sessions. My API login at 11:30 may therefore also explain the devotee app being on the login screen at the start of the run; I could not separate this from the DNS failure.
3. **Ghat completion asks for the code again after an app restart (low–medium).**
   - Steps: ghat booking, Start Puja with the booking code, restart or re-login the priest app, tap "2. Complete".
   - Actual: "Enter completion code" dialog ("Ask the devotee for the 4-digit completion code after the pooja.").
   - Expected: complete without a second code, as when the app is not restarted.
   - Cause: `DutyToggleScreen.kt:363` uses `verifiedStartCode`, which is in-memory only.
4. **My Offerings lists other priests' offerings (medium).** The screen calls `fetchCustomServices(lang=…)` without `priest_id` (`PriestServicesScreen.kt:41`), so the backend returns every active offering. "test" (priest 40cb5eb7…) and "Sri Venkateswara…" (priest f4a82408…) show as the test priest's own.
5. **New offering shows "Samagri Kit: +₹1500" although 0 was entered (low).** The server stored `samagri_kit_price_minor: 0` (S1-offering-published.png).
6. **Custom offerings cannot be deactivated or deleted (low).** No UI control and no backend endpoint. "E2E Offering 1126" remains active on staging.
7. **D3 still open:** "Could not refresh booking status. Check your connection." on return to the foreground, see retest item 2.
8. **Priest Pushkaralu tab shows the Live Studio placeholder after an in-app login** until the app is restarted (retest 5c).
9. Minor: the devotee catalogue search shows the full list when nothing matches ("E2E"); priest Telugu Duty Radar keeps the English "Location updated…" message; ghat Telugu name is the event name, and Hindi falls back to it (CMS data).

No lines in `adb logcat -b crash` during the run.
