## Findings

1. **Countdown mismatch:** Send an immediate ghat request. Devotee displayed 4:59 initially; priest displayed 39s shortly afterward. Expected the same deadline on both sides. Backend live aeb3f89 omits request_expires_at from booking list responses; local f9d09ad adds it, but causation was not verified by deploying. F2-request.png, F3-priest.png.
2. **Stale location hides an on-duty priest:** An approved, online priest with an Available duty initially did not appear. Database inspection showed location timestamp two days old; the Update my location button refreshed it and the priest appeared. The 15-minute freshness rule is intentional in code; the app still presented Online/Available without warning that discovery had expired. E-event.png, F1-priests.png, F1-refreshed.png. Automatic refresh behavior was not tested.
3. **Incorrect staging fixture:** ghat suskfnk had coordinates 68,30 and displayed 6726.2 km. At user's explicit request, updated this one ghat to 16.99,81.78, an approximate emulator test point, not a surveyed real ghat. Afterward distance was 0.0 km. D2-nearest.png, D2-corrected.png.
4. **Wrong-code feedback is generic:** wrong code displayed “Could not update status. Please try again.” rather than identifying an incorrect code. It did not start the ritual, but card status displayed “Priest has arrived”. F5-wrong.png.
